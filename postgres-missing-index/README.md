# Инцидент «Отчёты по клиентам тормозят»

## Ситуация

Сервис отчётов `sales-api` показывает продажи по клиенту. После вчерашнего релиза отчёты стали открываться заметно дольше, хотя данных почти не прибавилось.

```bash
time curl --silent http://127.0.0.1:8080/customers/4242/sales
```

Ошибок нет, ответы правильные — просто медленные.

## Топология

```text
клиент → sales-api 127.0.0.1:8080 → PostgreSQL 16 (Unix-сокет, база incidentsim)
```

- `incidentsim-sales-api.service` — HTTP-сервис: `GET /healthz`, `GET /customers/<id>/sales` (число продаж, сумма и дата последней продажи клиента).
- `postgresql@16-main.service` — кластер PostgreSQL. История продаж — таблица `sales` в базе `incidentsim`.

## Задача

Найдите, почему отчёты по клиентам стали медленными, и верните им прежнюю скорость. Сервис работает в продакшене: исправление не должно останавливать чтение и запись таблицы `sales`.

Ограничения:

- контракт и код `sales-api` менять нельзя;
- данные о продажах терять нельзя.

## Критерий готовности

```bash
bin/incidentctl verify postgres-missing-index
```

Проверка запрашивает отчёты по нескольким случайно выбранным клиентам. Каждый ответ должен быть правильным и приходить не дольше чем за 0,1 секунды.

## Управление сценарием

```bash
bin/incidentctl infra postgres-missing-index
bin/incidentctl incident postgres-missing-index
bin/incidentctl verify postgres-missing-index
```

После `incident` проверка должна падать, пока проблема не устранена.
